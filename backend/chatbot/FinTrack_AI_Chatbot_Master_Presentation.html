Executive Overview & Architecture

FinTrack: Multilingual WhatsApp AI Financial Assistant

Powered by Google MuRIL, Dual-Head PyTorch Transformers, FastAPI Microservice, Node.js/Express, & Twilio

The Core Problem

  • Manual expense tracking in GUI apps suffers from >70% user drop-off within 14 days.
  • Traditional bots require rigid syntax: ADD EXPENSE 250 FOOD.
  • Indian consumers naturally text in Hinglish (Code-Mixed): "yaar 250 ka pizza mangaya".

The AI Solution

  • Fine-tuned Google MuRIL (Multilingual Representations for Indian Languages).
  • Dual-Head Neural Architecture: Jointly predicts Transaction Type (Income/Expense) and Category (15 classes).
  • Hybrid regex + deterministic keyword pipeline for sub-millisecond execution.

Production Ecosystem

  • FastAPI Microservice (Port 8000) with in-memory model caching & API key authentication.
  • Node.js/Express (Port 5000) orchestrating Twilio WhatsApp webhooks, HMAC validation, and MongoDB.
  • Interactive commands: balance, budget, recent, link.

Demonstration Trigger: Sending "amazon se 1800 ke shoes liye" via WhatsApp extracts ₹1800, detects Expense, classifies Shopping via MuRIL, updates MongoDB Atlas, and returns real-time balance & budget status in < 250ms.

Machine Learning Rigor

Data Leakage Prevention & Class Weighting

Mathematical mitigation of phrase memorization and class imbalance

The Data Leakage Trap (Steps 9 & 10)

  • Financial logs repeat identical notes (e.g., hundreds of entries saying "swiggy" or "petrol").
  • A standard random train_test_split() puts exact duplicates into both train and test partitions.
  • The transformer simply memorizes string hashes, yielding a deceptive 99% test score that collapses on unseen real-world phrases.
  • Solution: Implemented Text-Disjoint Group Splitting: 
    Train_Unique_Texts ∩ Val_Unique_Texts = ∅

Tempered Class Weighting (Step 20)

  • Dataset had high class imbalance: Food had >1,200 rows, while Festivals had <40 rows.
  • Standard Inverse-Frequency weights: $w_c = \frac{N}{N_c}$. For rare classes, this generates massive multipliers causing explosive gradient spikes.
  • Tempered Inverse Frequency Formula:
wc = ( N / Nc )α,   with α = 0.5

Mathematical Foundations

The Mathematics of Transformer Self-Attention

Formulas governing token representation, query-key scaling, and projection

Scaled Dot-Product Attention

Attention(Q, K, V) = softmax( (Q KT) / √dk ) V

  • Query ($Q$), Key ($K$), Value ($V$): Projections of input embeddings via learned weight matrices $W^Q, W^K, W^V \in \mathbb{R}^{768 \times 64}$.
  • Why divide by $\sqrt{d_k}$? As $d_k=64$ grows, dot products scale larger, pushing softmax into extreme regions with near-zero gradients. $\sqrt{d_k}$ normalizes the variance to $1.0$.

Multi-Head Attention (12 Heads)

MHA(Q,K,V) = Concat(head1, ..., head12) WO

  • Allows the model to jointly attend to information from different representation subspaces (e.g. monetary values, merchants, actions).
  • Final pooled [CLS] token representation $h_{\text{CLS}} \in \mathbb{R}^{768}$ captures entire sentence semantics.
PyTorch Implementation

Dual-Head Multi-Task Transaction Classifier

Shared transformer encoder with parallel Type and Category linear heads

Neural Network Structure

class TransactionClassifier(nn.Module):
    def __init__(self, bert_model, num_types=2, num_categories=15):
        super().__init__()
        self.bert = bert_model
        hidden = self.bert.config.hidden_size # 768
        self.dropout = nn.Dropout(0.1)
        self.type_head = nn.Linear(hidden, num_types)
        self.category_head = nn.Linear(hidden, num_categories)

    def forward(self, input_ids, attention_mask):
        output = self.bert(input_ids, attention_mask=attention_mask)
        pooled = output.pooler_output # [CLS] token
        pooled = self.dropout(pooled)
        type_logits = self.type_head(pooled)
        category_logits = self.category_head(pooled)
        return type_logits, category_logits

Joint Multi-Task Loss Formulation

ℒtotal = ℒcategory + λ · ℒtype   (λ = 0.5)

  • $\mathcal{L}_{\text{category}}$: Weighted Multi-Class Cross-Entropy across 15 categories with tempered class weights.
  • $\mathcal{L}_{\text{type}}$: Binary Cross-Entropy (Expense vs Income).
  • Multi-Task Learning acts as a regularizer, reinforcing category decision boundaries without additional parameter overhead.
Training Dynamics

Two-Stage Fine-Tuning & Checkpoint Evolution

From structured household logs to unstructured WhatsApp conversations

Stage 1: Base Fine-Tuning

  • Dataset: 15,000 formal English household notes.
  • Hyperparameters: AdamW, $\text{lr}=2\times 10^{-5}$, Batch Size 32, 5 Epochs.
  • Output Checkpoint: muril_original_best.pt (950 MB).
  • Failed on colloquial Hinglish WhatsApp messages (accuracy collapsed to 61%).

Stage 2: WhatsApp Domain Adaptation

  • Dataset: 1,200+ synthesized & real Hinglish conversational phrases across all 15 categories.
  • Hyperparameters: Lower learning rate $\text{lr}=1\times 10^{-5}$ to prevent catastrophic forgetting.
  • Output Checkpoint: muril_whatsapp_best.pt (950 MB).
  • Real-world WhatsApp classification accuracy reached 93.8%.

Examiner Q&A Session

Viva Voce Master Questions: Machine Learning & NLP

Targeted technical questions asked in university evaluations and defense panels

Q1: Why MuRIL instead of GPT-4 or standard BERT?

MuRIL was pre-trained on 17 Indian languages and transliterated pairs (Devanagari $\leftrightarrow$ Latin), runs locally with <30ms latency, and preserves Hinglish word boundaries without fracturing.

Q2: What is a Dual-Head Classifier?

A single shared 236M-parameter Transformer backbone with two separate output heads ($W_{\text{type}}$ and $W_{\text{cat}}$), cutting VRAM by 50% and utilizing multi-task joint regularization.

Q3: How did you prevent Data Leakage?

Implemented Text-Disjoint Group Splitting so identical repetitive phrases (e.g. "swiggy") never exist in both train and validation partitions.

Q4: What is Tempered Class Weighting?

Applied $w_c = (N/N_c)^{0.5}$ to prevent explosive gradient spikes on tiny classes while retaining balanced class representation.

Examiner Q&A Session

Viva Voce Master Questions: Architecture & Webhooks

System design, cryptographic verification, idempotency, and resiliency

Q5: How does Twilio Webhook Security work?

Validates Twilio's HMAC-SHA1 cryptographic signature in X-Twilio-Signature, hashing the URL and parameters using TWILIO_AUTH_TOKEN.

Q6: Why is Idempotency essential?

Network retries from Twilio could double-charge expenses. We cache MessageSids in memory for 30 minutes to return 200 OK without re-logging.

Q7: Why use a Hybrid Model?

Regex extracts numbers with 100% precision in $O(1)$ time, and keyword dictionaries handle merchants instantly, saving the 236M transformer for ambiguous sentences.

Q8: How does Phone Resolution work?

Two-tier MongoDB lookup: exact match followed by last-10-digit regex, with an interactive link <email> fallback command.
